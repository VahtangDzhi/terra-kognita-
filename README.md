# StreetWear Hub Bot — MVP

Telegram-бот для бренда одежды: каталог, оформление заказа в чате, FAQ.

## Структура проекта

```
streetwear_bot/
├── main.py              # точка входа, запускает бота
├── config.py            # читает токен и id админа из .env
├── data.py               # каталог товаров и FAQ (пока просто в коде)
├── keyboards.py           # все клавиатуры бота
├── states.py              # состояния FSM для оформления заказа
├── handlers/
│   ├── start.py           # /start и главное меню
│   ├── catalog.py         # просмотр каталога
│   ├── faq.py              # вопросы-ответы
│   └── order.py            # пошаговое оформление заказа
├── requirements.txt
└── .env.example
```

## Как запустить

### 1. Получи токен бота
1. Напиши в Telegram боту **@BotFather**
2. Команда `/newbot`, придумай имя и username (должен заканчиваться на `bot`)
3. BotFather выдаст токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`

### 2. Узнай свой chat_id (куда будут падать заказы)
1. Напиши боту **@userinfobot**
2. Он покажет твой `Id` — это и есть ADMIN_CHAT_ID

### 3. Настрой проект
```bash
# создать виртуальное окружение (рекомендуется)
python3 -m venv venv
source venv/bin/activate   # на Windows: venv\Scripts\activate

# установить зависимости
pip install -r requirements.txt
```

Скопируй `.env.example` в `.env` и впиши туда токен и id:
```bash
cp .env.example .env
```

Открой `.env` и замени:
```
BOT_TOKEN=123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
ADMIN_CHAT_ID=123456789
```

### 4. Запусти бота
```bash
python main.py
```

Если всё настроено верно — в консоли появится лог о старте, и бот начнёт отвечать в Telegram. Напиши ему `/start`.

## Как это устроено (для обучения)

- **Router** — это "распределитель" сообщений. Каждый файл в `handlers/` — отдельный роутер со своим набором правил: "если пришло вот такое сообщение/кнопка — выполни вот эту функцию".
- **FSM (states.py)** — механизм "запоминания, на каком шаге диалога находится пользователь". Когда бот спросил "Как тебя зовут?", он переключает пользователя в состояние `waiting_name`. Следующее сообщение от этого пользователя попадёт именно в хендлер, который ждёт имя — а не куда-то ещё.
- **callback_data** — невидимая "метка", которая прикручена к каждой inline-кнопке. Когда юзер её нажимает, бот получает эту метку и понимает, что выбрали (например `item:hd1` значит "выбран товар с id hd1").

## Что добавить в версии 2 (для практики)

1. **SQLite вместо словарей в data.py** — чтобы хранить заказы и историю, а не терять всё после перезапуска
2. **Реальные фото товаров** — `bot.send_photo()` вместо текстовых карточек
3. **AI-ответы на свободные вопросы** — подключить Claude/OpenAI API для хендлера, который ловит любой текст вне FSM-состояний
4. **Админ-команды** — `/add_item`, `/orders` чтобы управлять каталогом и видеть список заказов прямо в боте
5. **Деплой 24/7** — Railway.app или Render.com (бесплатный тариф достаточен для старта)

## Деплой на Railway (когда будешь готов)

1. Залей проект в репозиторий на GitHub
2. Зарегистрируйся на railway.app, "New Project" → "Deploy from GitHub repo"
3. В настройках проекта добавь переменные окружения `BOT_TOKEN` и `ADMIN_CHAT_ID` (те же значения, что в .env)
4. Railway сам определит `main.py` и запустит — бот будет работать 24/7, даже когда твой компьютер выключен
